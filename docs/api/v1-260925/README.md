## 怎么用这一版

在请求路径**最后一段**写版本号：

```bash
curl 'https://api.firebounce.today/api/denick/v1-260925?nick=theoshadow' \
  -H 'X-API-Key: bsk_...'
```

适用于**每一个** `/api/<端点>`：`/api/player/v1-260925`、`/api/player/card/v1-260925`、
`/api/bancheck/v1-260925` … 版本号永远在最后。

> ⚠️ **只有字符串 `v1-260925` 本身会被当成旧版。**
> 服务端判定"是否走旧契约"是一次**精确字符串比较**，所以：
>
> - 写 `v1-250101` 之类的其它日期 → 路由会接受，但**返回当前版行为**，不是那天的行为。
> - 写 `v1` 或省略版本号 → **当前版**（会有英文文案和信封三件套）。
>
> 别用"随便哪个旧日期"当冻结档，只有 `v1-260925` 是。

## 与 `v1-261001` 的差异

**只有三类差异，没有字段被改名或删除，额度规则也没有变。**

| # | 项 | `v1-260925` | `v1-261001` |
| ---: | --- | --- | --- |
| 1 | 服务端生成的文案 | **中文** | 英文 |
| 2 | 响应信封 | 只有 `{ok, data}` | 多 `api_version` / `locale` / `schema` |
| 3 | `/api/bancheck` 的机器字段 | 只有 `known` / `banned` | 多 `state` / `data_quality` |
| 4 | `/api/player/card` 的 `ban_status` 块 | **不返回** | 返回 |

### 1. 文案语言

卡片里的块标题、单元格标签、页脚、状态文案在旧版是中文
（`封禁状态` / `已封禁` / `未封禁` / `数据可能不完整` / `演示数据` …）。

**玩家名、公会名、披风名、反作弊标签内容、上游原始字段两版都一样是原样数据。**

### 2. 响应信封

旧版响应**没有**这三个顶层字段：

```json
{"api_version": "v1-261001", "locale": "en", "schema": 1}
```

响应头 `X-API-Version` / `X-API-Latest` **两版都有**（它们是路由层加的，与版本无关）。

### 3. `/api/bancheck`

旧版**没有** `state`（`banned` / `not_banned` / `unknown`）和
`data_quality`（`complete` / `partial` / `no_record`）。其余字段
（`known`、`banned`、`source`、`sources[]`、`banned_at`、`name`、`uuid`、`query`、`cost`）两版相同。

**旧版下判断"无记录"只能靠 `known: false` + `banned: null`。**
升级到新版后请改用 `state` / `data_quality` —— 它们能区分
"确定没被封" 和 "没查到"。

### 4. `/api/player/card` 的封禁块

旧版卡片**不包含** `ban_status` 块。**`banned_days_ago` 这个字段只在卡片的
`ban_status` 里存在**，所以旧版拿不到它；`/api/bancheck` 两版都没有这个字段。

## 什么**没有**变

以下在两版之间**完全一致**，升级不会影响：

- **全部请求参数**（名字、位置、必填性、默认值、校验规则）
- **所有路径与别名**（含 `/api/checkban`、`/api/card.png` 的 `410`）
- **全部 24 个永久参数 ID**
- **基础额度**（`denick` 1、`player`/`tags`/`card` 1.5、`bancheck` 0.7/1.0、
  `search`/`recent`/`nick-history` 1、反代 1、`quota` 0）
- **体积加权档位**（3 MB / 5 MB → 7 / 15）
- **限速与闸门**（每 Key 120/分钟、玩家闸门 90/分钟、并发闸门 20、
  反代 600/分钟、quota 10/分钟）
- **缓存策略**（卡片 90 / 1800 / 64 条；反代 300 秒 / 512 条）
- **两个透明反代的全部行为**（Hypixel 与 Bugland）

> 卡片缓存在两版之间是**分开的**（缓存键带 `legacy:` / `modern:` 前缀），
> 所以同一个人在两版下各有一份缓存，不会互相串味。

## 从旧版迁到新版

改动很小，通常只是三件事：

1. 如果解析服务端文案 → 改成**服务端文案只用于显示**，程序判断一律用
   `state` / `data_quality` / `error` 等稳定字段。
2. 如果依赖"无记录 = 没被封" → 改成读 `state`，把 `unknown` 与 `not_banned` 分开处理。
3. 如果对响应做了严格的 schema 校验 → 允许新增的 `api_version` / `locale` / `schema`
   三个顶层字段（**不要**用"字段集合必须完全相等"这种校验）。

迁完把路径里的 `/v1-260925` 换成 `/v1-261001` 即可。
